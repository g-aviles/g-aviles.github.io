Professional self-assessment

How I approach computer science

Completing the Computer Science program has changed the way I approach technical problems. I now look beyond whether a program works and consider whether it is secure, maintainable, efficient, and useful to the people who depend on it.

Throughout the program, I developed skills in mobile application development, algorithms, databases, software testing, and user-interface design. More importantly, I learned how these areas work together to support a complete computing solution. Effective software begins with a clear understanding of the user’s needs, applies an appropriate technical design, protects the data it handles, and presents information in a way that its intended audience can understand. The enhancements in this portfolio demonstrate my progression from completing individual programming assignments to evaluating and improving complete software systems.

My coursework also strengthened my approach to collaboration and communication. I learned that successful collaboration depends on listening carefully, explaining technical decisions clearly, documenting work consistently, and remaining open to feedback. Code reviews, meaningful comments, organized project structures, and descriptive naming conventions allow other developers to understand and maintain a solution. Communication with nontechnical stakeholders requires a different approach because technical results must be translated into useful information without sacrificing accuracy. The Customer Order and RMA Dashboard demonstrates this ability by presenting thousands of database records through understandable filters, summary metrics, charts, and tables. It also avoids conclusions about revenue and time-based trends because the source data does not contain the information needed to support those claims.

The Course Plan Manager enhancement demonstrates my ability to apply data structures and algorithms to a practical problem. The original project relied on a binary search tree, while the enhanced solution uses hash maps to provide average O(1) course lookups, sets to prevent duplicate relationships, and forward and reverse adjacency lists to represent prerequisite connections. Depth-first search detects circular prerequisites in O(V + E) time, and a linear comparison process previews changes between different course-plan versions. Developing this enhancement improved my ability to select data structures according to the operations a system must perform. It also strengthened my understanding of the trade-offs among execution speed, memory usage, validation, and maintainability.

The Timely enhancement represents my growth in software engineering and application design. I originally developed Timely as a Java application for Android and later rebuilt it with Flutter and Dart. The enhanced version uses a shared cross-platform codebase and a more modular structure with clearer separation among the interface, authentication, event-management, and data-access components. I also added input validation, automated tests, password hashing, account-specific event storage, and database migrations. This process required me to evaluate the limitations of the original application, learn a different framework and programming language, and recreate the application without losing its primary purpose.

The Customer Order and RMA Dashboard demonstrates my growth in database design and data analysis. I created a relational SQLite database, validated headerless source files before importing them, preserved the relationships among customers, orders, and return merchandise authorizations, and added indexes to support efficient retrieval. I centralized reusable create, read, update, and delete operations so that connections and transactions could be managed consistently. I then used Streamlit, pandas, and Plotly to transform the database into an interactive dashboard that supports filtering, analysis, and communication with different audiences.

Security has become an essential part of my development process rather than a feature considered only at the end of a project. Across these enhancements, I applied credential hashing, account-level data boundaries, parameterized queries, allowlists, foreign-key constraints, transaction rollback, and early input validation. These practices reduce the risk of unauthorized access, invalid data, SQL injection, and damaged relationships between records. They also demonstrate the importance of protecting confidentiality, integrity, and reliability throughout the design and implementation of a system.

Collectively, these artifacts represent the computer science professional I am becoming. I can review an existing system, identify meaningful opportunities for improvement, learn unfamiliar technologies, and support technical decisions with evidence. My professional goal is to continue developing accessible and dependable software while expanding my experience in cross-platform development, data-driven applications, automated testing, and secure system design. This portfolio documents what I have learned and provides a foundation for the work I hope to accomplish next.
